# 価格交渉機能 仕様書

## 画面構成

### メイン画面
- 価格交渉を担当する社員が、複数の発注先候補から最終的な発注先を1つ選び、交渉結果と最終見積書を入力する画面
- 画面内コンテンツ:
  - **交渉先**
    - 発注先候補を複数表示
    - 各候補ごとに交渉先連絡方法を入力
  - **交渉結果**
    - 発注先
    - 交渉金額
    - 交渉金額の税区分
    - 連絡事項
    - 最終見積書（1件以上、複数追加可能）
    - 注文書
  - **認可依頼ボタン**
    - 押下時にZodバリデーションを実行
    - バリデーション成功時は認可依頼API実行直前のペイロードを取得する
    - 現時点ではAPI呼び出しは行わず、ペイロードを `console.log` に出力する

---

## ステータス別の表示・編集制御

### ステータス
- 価格交渉前
- 価格交渉中
- 価格交渉認可待ち
- 価格交渉認可後

### 価格交渉前
- 交渉先は表示する
- 交渉先連絡方法は非活性
- 交渉結果は非表示
- 画面下部に「交渉開始」ボタンを表示する
- 「交渉開始」ボタン押下で価格交渉中へ遷移する

### 価格交渉中
- 交渉先連絡方法を活性にする
- 交渉結果を表示する
- 交渉結果の各入力フィールドを編集可能にする
- 最終見積書は入力フォームとして表示する
- 注文書はファイル選択として表示する
- 画面下部に「認可依頼」ボタンを表示する
- 「認可依頼」ボタン押下でZodバリデーションを実行し、成功した場合は価格交渉認可待ちへ遷移する

### 価格交渉認可待ち
- 交渉先連絡方法は非活性
- 交渉結果は読み取り表示にする
- 発注先、交渉金額、連絡事項はテキストで表示する
- 交渉金額の税区分は交渉金額の横にテキストで表示する
- 最終見積書は入力フォームではなくカード形式で表示する
- 見積書ファイルはファイル名リンク相当のテキストとして表示する。ファイルがない場合は「-」を表示する
- 注文書はファイル名リンク相当のテキストとして表示する。ファイルがない場合は「-」を表示する
- 画面下部に「認可」ボタンを表示する
- 「認可」ボタン押下で価格交渉認可後へ遷移する
- 最終見積書のみ、カード単位で編集・削除できる
  - 発注先、交渉金額、交渉金額の税区分、連絡事項、注文書は編集不可
  - 最終見積書カード右上に3点リーダーボタンを表示する
  - 3点リーダーボタン押下で「編集」「削除」を選択できる
  - 「編集」選択時、その最終見積書カードだけ入力フォーム表示に切り替える
  - 編集対象フィールドは見積金額、見積日、税区分、見積No.、見積書ファイル、受領区分
  - 編集中は「保存」「キャンセル」ボタンを表示する
  - 「保存」押下時はZodバリデーションを実行し、成功した場合はフォーム値に反映して読み取り表示へ戻る
  - 実運用では「保存」押下時にAPIミューテーションを実行し、DBへ保存する想定
  - 「キャンセル」押下時は編集開始前の値で初期化し、読み取り表示へ戻る
  - 「削除」は2件目以降の最終見積書のみ可能
  - 1件目の最終見積書は削除不可

### 価格交渉認可後
- 交渉先連絡方法は非活性
- 交渉結果は読み取り表示にする
- 表示形式は価格交渉認可待ちと同じ
- 最終見積書のみ、価格交渉認可待ちと同じくカード単位で編集・削除できる
- 保存時は将来的にAPIミューテーションを実行し、DBへ保存する想定

## 交渉先

### 発注先候補
- 発注先候補はコンポーネント外から渡される配列として扱う
- 現実装ではコンポーネント実装に閉じるため、デモ用のダミーデータを使用する
- 将来的にはページ表示時、または親コンポーネント側でクエリを実行して候補一覧を取得する想定

### 交渉先連絡方法
- 各発注先候補ごとに入力する
- 入力形式: ラジオボタン
- 選択肢:
  - メール
  - TEL
- 初期値: 未選択
- 必須入力
- 未選択で認可依頼ボタンを押した場合:
  - ラジオボタングループのボーダーを赤にする
  - フィールド下にエラーメッセージを表示する
  - 認可依頼処理は実行しない
- 候補ごとの値は `candidates[index].contactMethod` としてフォーム値に保持する

---

## 交渉結果

### 発注先
- 入力形式: セレクトボックス
- 発注先候補の中から1つ選択する
- 必須入力
- 未選択で認可依頼ボタンを押した場合:
  - 入力フィールドのボーダーを赤にする
  - 入力フィールド下にエラーメッセージを表示する
  - 認可依頼処理は実行しない

### 交渉金額
- 入力形式: 数値入力
- 必須入力
- 整数のみ許容
- 未入力または整数でない場合:
  - 入力フィールドのボーダーを赤にする
  - 入力フィールド下にエラーメッセージを表示する
  - 認可依頼処理は実行しない

### 交渉金額の税区分
- 入力形式: ラジオボタン
- 選択肢:
  - 税込
  - 税抜
- 初期値: 税込

### 連絡事項
- 入力形式: テキストエリア
- 任意入力
- 最大500文字
- 最大文字数を超過した場合:
  - 入力フィールドのボーダーを赤にする
  - 入力フィールド下にエラーメッセージを表示する
  - 認可依頼処理は実行しない

---

## 最終見積書

### 基本仕様
- 最終見積書は1件以上必須
- 初期表示では1件目の最終見積書フォームを表示する
- **1件目は削除不可**
- 2件目以降は削除可能
- 「最終見積書追加」ボタンで新しい最終見積書フォームを追加する
- 最終見積書の配列は React Hook Form の `useFieldArray` で管理する

### レイアウト
- 1行目:
  - 左: 見積金額
  - 右: 見積日
- 2行目:
  - 左: 税区分
  - 右: 見積No.
- 3行目:
  - 見積書ファイル
- 見積書ファイル選択後:
  - 見積書ファイルの下に受領区分を表示する

### 見積金額
- 入力形式: 数値入力
- 必須入力
- 整数のみ許容
- 未入力または整数でない場合:
  - 入力フィールドのボーダーを赤にする
  - 入力フィールド下にエラーメッセージを表示する

### 見積日
- 入力形式: 日付入力
- 必須入力
- 未入力の場合:
  - 入力フィールドのボーダーを赤にする
  - 入力フィールド下にエラーメッセージを表示する

### 税区分
- 入力形式: ラジオボタン
- 選択肢:
  - 税込
  - 税抜
- 初期値: 未選択
- 必須入力
- 見積書ごとに値を保持する
- 未選択で認可依頼ボタンを押した場合:
  - ラジオボタングループのボーダーを赤にする
  - フィールド下にエラーメッセージを表示する
  - 認可依頼処理は実行しない

### 見積No.
- 入力形式: テキスト入力
- 任意入力
- 最大50文字
- 最大文字数を超過した場合:
  - 入力フィールドのボーダーを赤にする
  - 入力フィールド下にエラーメッセージを表示する

### 見積書ファイル
- 入力形式: ファイル選択
- 任意入力
- ファイルを選択した場合、フォーム値として以下を保持する
  - `file`: ブラウザ上の `File`
  - `fileName`: ファイル名
  - `filePath`: APIパラメータ連携用のファイルパス相当文字列
- 現時点では実アップロード処理は行わない
- 将来的には認可依頼APIの前段、またはAPIパラメータ生成時にファイルIDやファイルパスへ変換する想定

### 受領区分
- 見積書ファイルが選択された場合のみ表示する
- 入力形式: セレクトボックス
- 選択肢:
  - 電子
  - 紙
- 見積書ファイルが選択されている場合は必須入力
- 見積書ファイルが未選択の場合は表示せず、必須でもない
- 見積書ファイルが選択されていて受領区分が未選択の場合:
  - 入力フィールドのボーダーを赤にする
  - 入力フィールド下にエラーメッセージを表示する
  - 認可依頼処理は実行しない

## 注文書

  - `file`: ブラウザ上の `File`
  - `fileName`: ファイル名
  - `filePath`: APIパラメータ連携用のファイルパス相当文字列

## 認可依頼ボタンのバリデーション

### 基本動作
- 認可依頼ボタン押下時にフォーム全体をZodで検証する
- エラーがある場合:
  - 該当入力フィールドのボーダーを赤にする
  - 該当入力フィールド下に赤いエラーメッセージを表示する
  - ペイロード生成後のAPI処理には進まない
- エラーがない場合:
  - React Hook Form のフォーム値から認可依頼API直前のペイロードを生成する
  - 現時点では `console.log` に出力する

### バリデーション対象フィールド

| フィールド | ルール | エラーメッセージ |
|-----------|--------|--------------|
| 交渉先連絡方法（candidates[].contactMethod） | 空でないこと | 「交渉先連絡方法は必須です」 |
| 発注先（result.supplierId） | 空でないこと | 「発注先を選択してください」 |
| 交渉金額（result.negotiatedAmount） | 空でない・NaNでない / 整数 | 「金額は必須です」 / 「金額は整数で入力してください」 |
| 連絡事項（result.contactMemo） | 500文字以内 | 「連絡事項は500文字以内で入力してください」 |
| 最終見積書配列（result.quotations） | 1件以上 | 「最終見積書は1件以上入力してください」 |
| 見積金額（result.quotations[].amount） | 空でない・NaNでない / 整数 | 「金額は必須です」 / 「金額は整数で入力してください」 |
| 見積日（result.quotations[].quotationDate） | 空でないこと | 「見積日は必須です」 |
| 最終見積書の税区分（result.quotations[].taxType） | 空でないこと | 「税区分は必須です」 |
| 見積No.（result.quotations[].quotationNo） | 50文字以内 | 「見積No.は50文字以内で入力してください」 |
| 受領区分（result.quotations[].receiptCategory） | 見積書ファイル選択時のみ空でないこと | 「受領区分は必須です」 |

> 交渉金額の税区分は初期値があり、未選択状態が発生しないため通常の必須エラーは発生しない。

### 見積書ファイルと受領区分の条件付きバリデーション
- 見積書ファイルが未選択の場合:
  - 受領区分は表示しない
  - 受領区分の必須チェックは行わない
- 見積書ファイルが選択済みの場合:
  - 受領区分を表示する
  - 受領区分を必須チェックする
- 条件付きバリデーションは `finalQuotationSchema.superRefine` で定義する

## ペイロード生成

### フォーム内部データ
- フォーム内部では、ファイル入力を `StoredFile` として保持する

```ts
interface StoredFile {
  file: File | null;
  fileName: string;
  filePath: string;
}
```

### 認可依頼直前のペイロード
- 認可依頼時のペイロードでは、ファイル本体 `File` は送信対象から外す
- 見積書ファイル・注文書ファイルは `fileName` / `filePath` のみを含める
- API呼び出しは現時点では未実装

## 具体例（動作確認ケース）

| # | シナリオ | 結果 | 理由 |
|---|---------|------|------|
| 1 | 初期表示のまま認可依頼 | **阻止** | 発注先・交渉金額・見積金額・見積日が未入力 |
| 2 | 発注先のみ選択して認可依頼 | **阻止** | 交渉金額・見積金額・見積日が未入力 |
| 3 | 発注先・交渉金額・見積金額・見積日を入力して認可依頼 | **成功** | 必須項目が入力済み |
| 4 | 見積書ファイル未選択で認可依頼 | **成功** | 見積書ファイルは任意 |
| 5 | 見積書ファイル選択後、受領区分未選択で認可依頼 | **阻止** | ファイル選択時は受領区分が必須 |
| 6 | 見積書ファイル選択後、受領区分を選択して認可依頼 | **成功** | ファイルと受領区分のセットが valid |
| 7 | 最終見積書を追加し、2件目が空のまま認可依頼 | **阻止** | 2件目の見積金額・見積日が未入力 |
| 8 | 最終見積書を2件入力して認可依頼 | **成功** | 全見積書が valid |
| 9 | 2件目以降の最終見積書を削除 | **成功** | 2件目以降は削除可能 |
| 10 | 1件目の最終見積書を削除 | **不可** | 1件目は削除ボタンを表示しない |
| 11 | 連絡事項を501文字以上入力して認可依頼 | **阻止** | 最大文字数超過 |
| 12 | 見積No.を51文字以上入力して認可依頼 | **阻止** | 最大文字数超過 |
| 13 | 注文書ファイル未選択で認可依頼 | **成功** | 注文書は任意 |
