# 発注明細機能 仕様書

## 画面構成

### メイン画面
- タブ切り替え（現時点では「発注明細」タブのみ）
- タブ内コンテンツ:
  - **発注名**（テキスト入力フィールド）
  - **発注明細追加ボタン** → 押下で明細追加モーダルを表示
  - **見積書ごとの明細テーブル**（明細追加後に表示）
    - カラム: 商品名 / 商品型 / 金額
    - 各テーブルに小計
  - **サマリー表示**（明細テーブルの下に配置）
    - 価格交渉金額: 常時表示
    - 発注金額: 明細追加後に表示
    - 消費税: 明細追加後に表示
  - **認可依頼ボタン**
    - 明細が1件以上ないと非活性
    - 押下時に価格交渉金額と発注金額の一致をチェック
      - 不一致の場合: エラーメッセージを表示し、送信しない
      - 一致の場合: 発注名 + 全明細データをペイロードとして取得（将来的にAPI送信）
    - エラーは明細を再編集するとクリアされる

### 発注明細追加モーダル

#### 左側
- **見積書選択（セレクトボックス）**
  - 見積書IDの配列はページアクセス時に取得済み
  - セレクトボックスなので常に1つだけ選択
  - 見積書が1件も連携されていない場合は選択欄の代わりに「連携された見積書はありません」を表示し、明細は手入力できる
- **税区分（ラジオボタン）**
  - 税抜（初期値）/ 税込
  - 税区分は明細の税率フィールドの活性状態に影響しない
- **見積書プレビュー**（プレースホルダー）

#### 右側（明細入力フィールド）
- **見積書未選択時（初期表示）**: 見積書が1件以上ある場合、空の明細1行と「明細を追加」ボタンが表示されるが、**すべて非活性**（入力フィールド・明細を追加ボタン・フッターの明細追加/更新ボタン）
  - 税区分ラジオボタンは非活性対象外（常時活性）
- **見積書0件時**: 例外的に初期表示から入力フィールド・明細を追加ボタン・フッターの明細追加/更新ボタンが活性になり、見積書なしの明細として保存できる
- **見積書選択時**: 入力フィールドと各種ボタンが活性化され、選択した見積書の明細が編集可能になる
- 各明細行のフィールド:
  - 商品名（テキスト、最大100文字）
  - 商品型番号（テキスト、最大75文字）
  - 単価（数値、負数可、0不可、空欄可）
  - 数量（数値、空欄可、0不可）
  - 税率（セレクト: 非課税 / 8% / 10%、初期値10%、見積書選択時は常時活性）
  - 金額（整数、手動入力、負数可、0不可。入力欄でも小数点は受け付けない）
- 「明細を追加」ボタン → 新しい明細行を追加（見積書選択時、または見積書0件時のみ活性）

#### フッター
- **キャンセル** → モーダルを閉じてフォームリセット
- **明細追加/更新** → 見積書選択時、または見積書0件時のみ活性。押下時にZodバリデーションを実行し、通過すればモーダルを閉じてメイン画面に反映

## モーダル再オープン時の挙動

### 初回オープン（明細未登録）
- 全フィールド空の初期状態で表示
- モーダルタイトル: 「発注明細追加」
- 保存ボタン文言: 「明細追加」
- メイン画面のボタン文言: 「発注明細追加」

### 再オープン（明細登録済み）
- 前回保存した内容で初期セットされる
- 最初の見積書が選択状態で表示
- モーダルタイトル: 「発注明細編集」
- 保存ボタン文言: 「更新」
- メイン画面のボタン文言: 「発注明細編集」

### 保存時のデータ処理
- 追加ではなく **上書き**
- 既存の明細は新しい内容で丸ごと置換される

## 見積書切り替え時の挙動

### 基本動作
- 見積書1を選択 → 右に見積書1の明細フィールドが表示
- 見積書2に切り替え → 見積書1のフィールドが消え、見積書2のフィールドが表示

### 入力値の保持
- 見積書1で入力後、見積書2に切り替え、再び見積書1に戻ると入力値が保持されている

### 初期表示
- **未入力の見積書を選択した場合**: 空の明細1行がデフォルト表示される
- **見積書0件の場合**: 初期表示の空の明細1行をそのまま手入力用として使用する
- **別の見積書のフィールド数・入力内容が影響してはならない**

### 見積書切替時のバリデーション
- 現在の見積書から別の見積書に切替えようとした際、現在の見積書の**全明細行**をZodで検証
- **バリデーション失敗**: 切替を阻止し、エラーメッセージを各フィールド下に表示。選択状態は元の見積書のまま
- **バリデーション成功**: エラーをクリアして切替
- **完全に空の行・部分入力済みの行**: いずれも検証対象。必須項目が未入力なら必須エラーを出す
- 不要な行は削除ボタン（ゴミ箱）で取り除いてから切替する

## 明細追加/更新ボタンのバリデーション

### ボタン状態
- 見積書選択時のみ活性。ただし見積書0件の場合は例外的に初期表示から活性
- クリック時に**現在表示中の見積書の全明細行**を `detailItemSchema` で検証
  - 他の見積書は「切替成功時にその見積書の検証を通過している」不変条件により常に valid のため、再検証不要
- エラーがあれば各フィールド下にメッセージ表示、保存しない
- エラーがなければ保存処理を実行

### バリデーション対象フィールド
| フィールド | ルール | エラーメッセージ |
|-----------|--------|--------------|
| 商品名（productName） | 空でないこと / 100文字以内 | 「商品名は必須です」 / 「商品名は100文字以内で入力してください」 |
| 商品型番号（modelNumber） | 75文字以内 | 「商品型番号は75文字以内で入力してください」 |
| 単価（unitPrice） | 空欄可。入力する場合は 0 以外（負数可） | 「単価は0以外を入力してください」 |
| 数量（quantity） | 空欄可。入力する場合は 0 以外 | 「数量は0以外を入力してください」 |
| 金額（amount） | 空でない・NaN でない / 整数 / 0 以外（負数可） | 「金額は必須です」 / 「金額は整数で入力してください」 / 「金額は0以外を入力してください」 |

### 単価・数量・金額の整合性
- 単価と数量がどちらも入力されている場合のみ、`単価 × 数量 = 金額` を検証する
- 単価または数量が空欄の場合は、金額との整合性チェックは行わない
- 単価が整数の場合は、入力された金額と `単価 × 数量` が完全一致していること
- 単価に小数点が含まれる場合は、丸め誤差として入力された金額と `単価 × 数量` の差分 `±1` まで許容する

> 税率（taxRate）は3択セレクトで初期値10%、未選択状態が発生し得ないためバリデーション対象外。

### 空の明細行の扱い
- 完全に空の行も含め、すべての明細行が必須チェック対象（productName・amount）
- 不要な行はゴミ箱アイコンで削除してから保存する
- 最低1行（最後の1行は削除不可）が常に存在するため、必ず1行以上の入力が要求される

### 具体例（動作確認ケース）

見積書切替・保存ボタン押下の双方で、**現在表示中の見積書の全明細行**を検証対象とする。
他の見積書は「切替成功時の検証」で valid 性が保証されているため、保存時に再検証しない。

#### 見積書切替

| # | シナリオ | 結果 | 理由 |
|---|---------|------|------|
| 1 | 見積書1選択直後（空の行1が1件のみ） → 見積書2へ切替 | **阻止** | 行1が必須未入力（空行も検証対象） |
| 2 | 見積書1の行1を全入力 → 見積書2へ切替 | **成功** | 行1が完全入力済み |
| 3 | 見積書1の行1を全入力 → 空の行2を追加 → 見積書2へ切替 | **阻止** | 追加した空の行2が必須未入力 |
| 4 | 見積書1の行1を部分入力（商品名のみ） → 見積書2へ切替 | **阻止** | 金額が必須未入力 |
| 4-2 | 見積書1の行1の商品名が101文字以上 → 見積書2へ切替 | **阻止** | 商品名が最大文字数超過 |
| 4-3 | 見積書1の行1の単価または金額が0 → 見積書2へ切替 | **阻止** | 単価・金額の0入力は不可 |
| 5 | 見積書1全入力 → 見積書2全入力 → 見積書1に戻す | **成功** | 両見積書とも入力済み |
| 6 | 見積書1全入力 → 見積書2に空の行2を追加 → 見積書1へ戻す | **阻止** | 見積書2の行2が未入力のまま |
| 7 | 見積書1全入力 → 空の行2を追加 → 行2を削除 → 見積書2へ切替 | **成功** | 不要な行は削除すれば切替可能 |

#### 明細追加/更新ボタン押下（保存）

保存時は **現在表示中の見積書のみ** を検証する。他の見積書は切替成功時の検証により valid であることが保証されている。

| # | シナリオ | 結果 | 理由 |
|---|---------|------|------|
| 8 | 見積書1のみ全入力（表示中） → 保存 | **成功** | 現在表示中の見積書1 の全行 valid |
| 9 | 見積書1・2ともに全入力（見積書1を表示中） → 保存 | **成功** | 現在が valid、見積書2も切替時検証で valid 済み |
| 10 | 見積書1全入力 + 空の行2追加（表示中） → 保存 | **阻止** | 現在表示中の見積書1 の行2が必須未入力 |
| 11 | 見積書1全入力 → 見積書2選択（空のまま）で表示中 → 保存 | **阻止** | 現在表示中の見積書2 の行1が必須未入力 |
| 12 | 見積書1選択直後（空の行1のみ）で表示中 → 保存 | **阻止** | 現在表示中の見積書1 の行1が必須未入力 |
| 13 | 見積書1・2ともに複数行を全入力（どちらか表示中） → 保存 | **成功** | 現在表示中が valid、もう一方も切替時検証で valid 済み |
| 14 | 商品名101文字以上 / 商品型番号76文字以上 → 保存 | **阻止** | 最大文字数超過 |
| 15 | 単価または金額が0 → 保存 | **阻止** | 単価・金額の0入力は不可 |
| 16 | 単価または金額が負数 → 保存 | **成功** | 割引ケースとして負数は許容 |
| 17 | 数量が0 → 保存 | **阻止** | 数量の0入力は不可 |
| 18 | 金額欄に小数を入力 | **小数点を受け付けない** | 金額は整数のみ許容 |
| 19 | 単価100・数量3・金額299 → 保存 | **阻止** | 金額が単価×数量と一致しない |
| 20 | 単価または数量が空欄・金額のみ入力 → 保存 | **成功** | 整合性チェック対象外 |
| 21 | 単価33.3・数量3・金額100 → 保存 | **成功** | 小数単価のため差分±1を許容 |

### 保存時の挙動
- バリデーションが通過した時点で、`quotationEntries` 内の全明細がそのまま保存される
- 空行・部分入力の行が混在することはない（事前にバリデーションで阻止される）
